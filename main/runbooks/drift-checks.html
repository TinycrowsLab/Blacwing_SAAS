Drift checks

The drift workflow (.github/workflows/drift.yml, CI-015) keeps generated contracts and the database in lockstep with code. It runs on every pull request and on main, with contents: read. TZ=UTC and LANG=C.UTF-8 are pinned so generation is deterministic.

What it checks

Check Fails when Fix
OpenAPI 3.1 pnpm openapi:generate changes docs/api/openapi.json Run pnpm --filter @blackwing/api openapi:emit (alias openapi:generate), commit
API reference pnpm openapi:generate changes docs/api/reference.md (the page is rendered from the spec) Run pnpm openapi:generate, commit
GraphQL SDL pnpm graphql:generate changes apps/api/schema.gql Run pnpm graphql:generate, commit
Persona catalogue pnpm gen:persona-catalogue changes docs/architecture/persona-catalogue.md (derived from the persona definitions) Run pnpm gen:persona-catalogue, commit
Schema vs migrations pnpm db:generate (drizzle-kit generate) emits a new file in packages/db/migrations/ Review and commit the generated migration
Forward-only A migration file that exists on the base branch is modified or deleted Add a new migration instead
db-drift job pnpm db:check: journal collisions, schema vs migrations, a scratch Postgres 16 + pgvector built from the migrations differs from the snapshot, or a re-run is not a no-op See db-migrations.md

Generators are the openapi:generate, graphql:generate and db:generate scripts of workspace members (pnpm -r --if-present), so each owning epic (API, DB) adds its script and the artifact paths listed in scripts/check-drift.mjs (ARTIFACTS). Generated files are formatted with Prettier before the diff; generators must sort keys and lists so output is stable.

Failures name the stale artifact and the command to run, in the job log and the step summary.

Baseline squash

Squashing the migration history is a deliberate, reviewed exception. Add the migration-squash label to the pull request; the forward-only check is then skipped for that PR. Do not use the label for anything else, and never squash after a migration has been applied to a shared or production database.

Local run

pnpm openapi:generate && pnpm graphql:generate && pnpm gen:persona-catalogue && pnpm db:generate
node scripts/check-drift.mjs stale
node scripts/check-drift.mjs immutable origin/main
pnpm db:check   # needs Docker (Testcontainers)

Public API spec and docs UI (API-003, #55)

docs/api/openapi.json is the OpenAPI 3.1 document of the public /v1 API, generated from the Zod contracts by apps/api/src/openapi/ and linted (3.1 meta-schema, unique operationIds, a Problem error response and an example on every operation) before it is written. pnpm --filter @blackwing/api openapi:check fails when the committed file is stale. The /internal/broker routes are never published. The interactive reference is served (self-hosted Swagger UI) at /v1/docs; in production it requires an authenticated caller and answers 401 otherwise. New modules add an OpenApiModule to publicOpenApiModules(); keep operationIds stable, the client generator (API-012) depends on them.
