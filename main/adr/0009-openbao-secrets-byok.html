ADR-0009: Manage secrets with OpenBao envelope encryption and bring-your-own-key references

Date: 2026-10-20

Status

Accepted

Context

Blackwing holds highly sensitive material for many tenants: target credentials per role, connector tokens, model provider keys, signing keys and evidence. The original feature list kept secrets in the customer's key store for a single-tenant on-prem install. A multi-tenant SaaS needs per-tenant cryptographic isolation it operates itself, while still letting customers keep keys or secrets in systems they control.

Decision

  • OpenBao, operated by Blackwing, is the secrets and key service: Transit for per-tenant envelope encryption and KV v2 for platform secrets, accessed through packages/secrets.
  • Customers can bring their own key or vault by reference: their AWS KMS key (cross-account), their HashiCorp Vault or OpenBao, AWS Secrets Manager or Azure Key Vault, each through a BYOK adapter.
  • Secrets are stored and passed by reference (secret_ref), never as plaintext columns. The session manager and the egress gateway inject credentials at use; agents, the model and logs never see them, and known secret values are redacted from tool output and in the model gateway.

Consequences

  • A compromise of one tenant's data key does not expose another tenant's data, and BYOK customers can revoke Blackwing's access by revoking their key.
  • Every component that needs a secret depends on OpenBao (or the BYOK adapter) being reachable; when it is not, the operation fails rather than falling back to a weaker store.
  • BYOK adapters are an integration surface per provider, each with its own tests and failure handling.
